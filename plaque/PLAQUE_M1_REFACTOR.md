# PLAQUE on AsterixDB — Milestone 1 Refactor

**Refactor of `PLAQUE_M1.md`:** decouple FilterState ownership from the filter. The wrapper **local aggregate owns and updates** the FilterState; the **filter only reads** from it. Both operators are wired to the same FilterState instance via Hyracks's standard per-task state-object registry.


## Why

M1 as originally written has a self-observing filter: the same operator both updates and reads the threshold. This collapses in M2 where the FilterState is fed by a remote publisher — the filter's per-tuple code would have to be rewritten to remove the update call and change its source of truth.

Decoupling now means:
- **Observation lives with the aggregate.** The aggregate already compares and updates its running max/min on every tuple — the exact information the filter needs. Reusing that comparison saves one type-aware compare per tuple and avoids the correctness risk of two independent comparators.
- **The filter becomes purely a reader.** Its `nextFrame()` body (`passes()` + `appendTupleToFrame`) does not change between M1 and M2. Only who writes to the FilterState changes.
- **M2 becomes a substitution, not a rewrite.** Swap the local-writer for a remote-writer; keep the reader.


## Design summary

```
     ┌───────────────────┐
     │ DATASOURCE_SCAN   │
     └─────────┬─────────┘
               ▼
     ┌───────────────────┐     reads only
     │ PlaqueFilter      │────────────────┐
     │ (SELECT annot.)   │                │
     └─────────┬─────────┘                ▼
               ▼                  ┌──────────────┐
     ┌───────────────────┐ writes │ FilterState  │
     │ local AGGREGATE   │───────▶│ (per-task)   │
     │ (plaque-wrapped)  │        └──────────────┘
     └─────────┬─────────┘
               ▼
     RANDOM_MERGE_EXCHANGE → global AGGREGATE
```

Both operators are micro-operators in the same partitioned pipeline on the same Hyracks task. They share the `IHyracksTaskContext`, so they share a FilterState through the task's state-object registry (`IOperatorEnvironment.setStateObject / getStateObject`). This is the same mechanism join operators use to share `BuildAndPartitionTaskState` / `JoinCacheTaskState` across activities on the same partition — see `NestedLoopJoinOperatorDescriptor.java:139,167` and `OptimizedHybridHashJoinOperatorDescriptor.java:326,408`.

## Design decisions

### Why `IHyracksTaskContext.setStateObject`, not a direct object reference

The two runtime factories (filter and wrapper aggregate) are **serializable**. They ship from CC → NC as part of the job spec. A shared Java object reference in the factories is lost across serialization — each NC deserializes two independent copies.

The established AsterixDB/Hyracks pattern for per-task shared state is `IOperatorEnvironment.setStateObject`. Both factories carry a **serializable handle** (`String` — a plan-unique key), and at runtime they use the handle to look up / register the same `FilterState` instance in the task context.

Not chosen:
- **Static `Map<handle, FilterState>`** — leaks across queries on long-lived NCs; tricky to clean up; cross-partition bleed. Task-context state is automatically scoped to the task.
- **Extending the aggregate's IAggregateEvaluator contract** — requires changes to `AggregatePOperator` / `AggregateRuntimeFactory`, which are shared code. State-object registry is already the blessed channel.

### Why a "create-if-absent" helper, not fixed ordering

Although open cascade *currently* goes source → filter → aggregate, we do not rely on that. Both the filter's `open()` and the wrapper aggregate's `createAggregateEvaluator(ctx)` call the same `FilterStateRegistry.getOrCreate(ctx, handle, isMax)`. Whichever runs first creates; the other looks up. This is safe because all micro-operators on one partition run on one thread.

### Why one key per plan site (not per aggregate function call)

The rule fires on a `(PlaqueFilter, local-aggregate)` pair. Both receive the same handle. The handle is generated at plan time (e.g., `"plaque-" + context.newVar().getId()`) and serialized with each factory. It is unique per plan site — different queries produce different handles; different aggregates in the same query (M2) produce different handles.

### Why a hook in `AbstractMinMaxAggregateFunction`, not a composition wrapper

A composition wrapper (`class PlaqueWrapper implements IAggregateEvaluator { IAggregateEvaluator inner; }`) cannot cheaply detect **"the running max strengthened on this tuple"** after `inner.step()` — the running max lives in `inner`'s private `outputVal` field. The wrapper would need to re-deserialize and re-compare, duplicating the aggregate's work.

The localized alternative: add a no-op protected hook `onMinMaxChanged()` inside `AbstractMinMaxAggregateFunction.compareAndUpdate()` and inside the first-value branch. `PlaqueLocalSqlMinMaxAggregateFunction extends SqlMinMaxAggregateFunction` overrides the hook to call `filterState.update(outputVal.getByteArray(), outputVal.getStartOffset(), outputVal.getLength())`. Zero extra per-tuple work when the running max does not change; one byte-array copy when it does.

This requires exposing `outputVal` (currently private) as `protected`, which is a single-visibility change to an existing class. No interface changes.


## Components to build (or change vs. `PLAQUE_M1.md`)

### 1. `FilterState` — now an `IStateObject`
**Path:** `asterixdb/asterix-runtime/src/main/java/org/apache/asterix/runtime/operators/plaque/FilterState.java`

**Changes vs. M1:**
- Extends `AbstractStateObject` so it can live in the task-context registry.
- Interface (`update()`, `passes()`) is unchanged.
- Construction does not take a key; the key is set externally by `FilterStateRegistry`.

```java
public class FilterState extends AbstractStateObject {
    private final boolean isMax;
    private final IBinaryComparator comparator;
    private byte[] thresholdBytes;
    private int thresholdLength;
    private boolean initialized;

    public FilterState(boolean isMax) {
        super();  // jobId and id set later by registry
        this.isMax = isMax;
        this.comparator = AGenericAscBinaryComparatorFactory.INSTANCE.createBinaryComparator();
        this.initialized = false;
    }

    /** Called ONLY by the wrapper aggregate when its running min/max strengthens. */
    public void update(byte[] data, int start, int len) throws HyracksDataException {
        if (!initialized) {
            thresholdBytes = new byte[len];
            System.arraycopy(data, start, thresholdBytes, 0, len);
            thresholdLength = len;
            initialized = true;
            return;
        }
        int cmp = comparator.compare(data, start, len, thresholdBytes, 0, thresholdLength);
        if ((isMax && cmp > 0) || (!isMax && cmp < 0)) {
            if (thresholdBytes.length < len) {
                thresholdBytes = new byte[len];
            }
            System.arraycopy(data, start, thresholdBytes, 0, len);
            thresholdLength = len;
        }
    }

    /** Called ONLY by the filter. Never mutates state. */
    public boolean passes(byte[] data, int start, int len) throws HyracksDataException {
        if (!initialized) return true;
        int cmp = comparator.compare(data, start, len, thresholdBytes, 0, thresholdLength);
        return isMax ? cmp >= 0 : cmp <= 0;
    }
}
```

**Threading note:** Within one partition, filter and aggregate run on the same thread (standard micro-op pipeline). The filter's `passes()` read of `thresholdBytes`/`thresholdLength` and the aggregate's `update()` write to the same fields interleave tuple-by-tuple on a single thread, so no locking or `volatile` is needed. (Cross-partition sharing is a M2 concern, not M1.)

### 2. `FilterStateRegistry` — create-if-absent helper
**Path:** `asterixdb/asterix-runtime/src/main/java/org/apache/asterix/runtime/operators/plaque/FilterStateRegistry.java`

New. Encapsulates the task-context registry lookup so the filter and the wrapper aggregate share one call site.

```java
public final class FilterStateRegistry {
    private FilterStateRegistry() {}

    public static FilterState getOrCreate(IHyracksTaskContext ctx, String handle, boolean isMax) {
        FilterState state = (FilterState) ctx.getStateObject(handle);
        if (state == null) {
            state = new FilterState(isMax);
            state.setJobId(ctx.getJobletContext().getJobId());
            state.setId(handle);
            ctx.setStateObject(state);
        }
        return state;
    }
}
```

Note: `ctx.getStateObject(id)` returns `null` when the key is absent — verified by grepping the join operator descriptors, which all use this get-then-set-if-null pattern.

### 3. `PlaqueFilterRuntime` — reader only
**Path:** `asterixdb/asterix-runtime/src/main/java/org/apache/asterix/runtime/operators/plaque/PlaqueFilterRuntimeFactory.java` (inner class)

**Changes vs. M1:** constructor no longer creates a `FilterState`. The runtime stores the handle and resolves the state in `open()` (before propagating `super.open()`, so the state is present in the registry when the aggregate opens next). `nextFrame()` **never** calls `update()`.

```java
public class PlaqueFilterRuntime extends AbstractOneInputOneOutputOneFramePushRuntime {
    private final int columnIdx;
    private final boolean isMax;
    private final String handle;
    private FilterState filterState;  // resolved in open()
    private IHyracksTaskContext ctx;

    PlaqueFilterRuntime(IHyracksTaskContext ctx, int columnIdx, boolean isMax, String handle) {
        this.ctx = ctx;
        this.columnIdx = columnIdx;
        this.isMax = isMax;
        this.handle = handle;
    }

    @Override
    public void open() throws HyracksDataException {
        initAccessAppendRef(ctx);
        // Create-or-fetch BEFORE super.open() — the aggregate's open()
        // (which will call createAggregateEvaluator) runs next in the cascade,
        // and must see the same FilterState instance we register here.
        filterState = FilterStateRegistry.getOrCreate(ctx, handle, isMax);
        super.open();
    }

    @Override
    public void nextFrame(ByteBuffer buffer) throws HyracksDataException {
        tAccess.reset(buffer);
        int nTuple = tAccess.getTupleCount();
        for (int t = 0; t < nTuple; t++) {
            tRef.reset(tAccess, t);
            byte[] data = tRef.getFieldData(columnIdx);
            int start = tRef.getFieldStart(columnIdx);
            int len = tRef.getFieldLength(columnIdx);
            byte typeTag = data[start];

            // Pass NULL/MISSING unchanged — the aggregate handles them.
            if (typeTag == ATypeTag.SERIALIZED_NULL_TYPE_TAG
                    || typeTag == ATypeTag.SERIALIZED_MISSING_TYPE_TAG
                    || typeTag == ATypeTag.SERIALIZED_SYSTEM_NULL_TYPE_TAG) {
                appendTupleToFrame(t);
                continue;
            }

            // READ-ONLY. No update() call.
            if (filterState.passes(data, start, len)) {
                appendTupleToFrame(t);
            }
        }
    }

    @Override
    public void flush() throws HyracksDataException {
        appender.flush(writer);
    }
}
```

### 6. `PlaqueLocalSqlMinMaxAggregateFunction` — the wrapper
**Path:** `asterixdb/asterix-runtime/src/main/java/org/apache/asterix/runtime/aggregates/std/PlaqueLocalSqlMinMaxAggregateFunction.java`

New. Subclasses `SqlMinMaxAggregateFunction` (which is itself `AbstractMinMaxAggregateFunction` for SQL semantics) and overrides the hook.

```java
public class PlaqueLocalSqlMinMaxAggregateFunction extends SqlMinMaxAggregateFunction {

    private final FilterState filterState;

    PlaqueLocalSqlMinMaxAggregateFunction(IScalarEvaluatorFactory[] args, IEvaluatorContext context,
            boolean isMin, SourceLocation sourceLoc, IAType aggFieldType, FilterState filterState)
            throws HyracksDataException {
        super(args, context, isMin, Type.LOCAL, sourceLoc, aggFieldType);
        this.filterState = filterState;
    }

    @Override
    protected void onMinMaxChanged() throws HyracksDataException {
        // outputVal is now the latest running min/max for this partition.
        filterState.update(
                outputVal.getByteArray(),
                outputVal.getStartOffset(),
                outputVal.getLength());
    }
}
```

**No new function identifier, no `BuiltinFunctions` entry.** The wrapper is selected via a custom physical operator on the existing `AggregateOperator` (below), not via the function-descriptor registry. This keeps the SQL++ surface and metadata untouched.

### 7. `PlaqueAggregatePOperator` — wraps the aggregate's runtime factory
**Path:** `asterixdb/asterix-algebra/src/main/java/org/apache/asterix/algebra/operators/physical/PlaqueAggregatePOperator.java`

New. Extends `AggregatePOperator` and overrides `contributeRuntimeOperator` to produce a `PlaqueLocalSqlMinMaxAggregateFunction` (§6) instead of the standard `SqlMinMaxAggregateFunction`.

**Why a custom POperator (not a new function identifier):** we don't want to change the logical plan's aggregate expression or register a new builtin. The rewrite rule pre-assigns this POperator on the existing `AggregateOperator`, and `SetAlgebricksPhysicalOperatorsRule` leaves it alone (same trick M1 already uses for `PlaqueFilterPOperator` on `SelectOperator`; see `SetAlgebricksPhysicalOperatorsRule.java:72`).

**Why inherit from `AggregatePOperator` and only override `contributeRuntimeOperator`:** `computeDeliveredProperties` / `getRequiredPropertiesForChildren` are correct as-is. The only behavior we change is how the `IAggregateEvaluatorFactory` is built.

**How it builds the factory:** The standard path (`expressionRuntimeProvider.createAggregateFunctionFactory`) does descriptor lookup + `setImmutableStates` + arg compilation internally. Rather than re-implementing that machinery, we call the standard path first to get the `inner` factory, then wrap it in a thin `PlaqueLocalAggregateEvaluatorFactory` (§8) that intercepts `createAggregateEvaluator` at runtime.

```java
public class PlaqueAggregatePOperator extends AggregatePOperator {

    private final String handle;
    private final boolean isMax;

    public PlaqueAggregatePOperator(String handle, boolean isMax) {
        this.handle = handle;
        this.isMax = isMax;
    }

    @Override
    public PhysicalOperatorTag getOperatorTag() {
        // Reuse AGGREGATE — no new tag needed. Plan-print can be distinguished
        // via the annotation on the logical operator.
        return PhysicalOperatorTag.AGGREGATE;
    }

    @Override
    public void contributeRuntimeOperator(IHyracksJobBuilder builder, JobGenContext context,
            ILogicalOperator op, IOperatorSchema opSchema, IOperatorSchema[] inputSchemas,
            IOperatorSchema outerPlanSchema) throws AlgebricksException {
        AggregateOperator aggOp = (AggregateOperator) op;
        List<Mutable<ILogicalExpression>> expressions = aggOp.getExpressions();
        IAggregateEvaluatorFactory[] aggFactories = new IAggregateEvaluatorFactory[expressions.size()];
        IExpressionRuntimeProvider expressionRuntimeProvider = context.getExpressionRuntimeProvider();

        for (int i = 0; i < aggFactories.length; i++) {
            AggregateFunctionCallExpression aggFun =
                    (AggregateFunctionCallExpression) expressions.get(i).getValue();
            // Step 1: Build the standard factory via the normal descriptor path.
            IAggregateEvaluatorFactory inner = expressionRuntimeProvider.createAggregateFunctionFactory(
                    aggFun, context.getTypeEnvironment(op.getInputs().get(0).getValue()),
                    inputSchemas, context);
            // Step 2: Wrap it so that at runtime, createAggregateEvaluator produces
            // a PlaqueLocalSqlMinMaxAggregateFunction bound to the shared FilterState.
            aggFactories[i] = new PlaqueLocalAggregateEvaluatorFactory(inner, handle, isMax);
        }

        AggregateRuntimeFactory runtime = new AggregateRuntimeFactory(aggFactories);
        runtime.setSourceLocation(aggOp.getSourceLocation());
        RecordDescriptor recDesc = JobGenHelper.mkRecordDescriptor(
                context.getTypeEnvironment(op), opSchema, context);
        builder.contributeMicroOperator(aggOp, runtime, recDesc);
        ILogicalOperator src = aggOp.getInputs().get(0).getValue();
        builder.contributeGraphEdge(src, 0, aggOp, 0);
    }
}
```

### 8. `PlaqueLocalAggregateEvaluatorFactory` — intercepts evaluator creation
**Path:** `asterixdb/asterix-runtime/src/main/java/org/apache/asterix/runtime/operators/plaque/PlaqueLocalAggregateEvaluatorFactory.java`

New. Serializable `IAggregateEvaluatorFactory` that wraps the standard factory produced by the normal descriptor path. At runtime, it calls `inner.createAggregateEvaluator(ctx)` to get the fully-initialized `SqlMinMaxAggregateFunction`, then wraps it in a `PlaqueLocalSqlMinMaxAggregateFunction`.

The wrapping works because `PlaqueLocalSqlMinMaxAggregateFunction extends SqlMinMaxAggregateFunction` and overrides `onMinMaxChanged()` (§5–6). The `inner` factory already handles descriptor lookup, `setImmutableStates`, arg compilation, and `SourceLocation` — we don't re-implement any of that.

**How the wrapper aggregate gets constructed from the inner evaluator:** `inner.createAggregateEvaluator(ctx)` returns a `SqlMinMaxAggregateFunction` (the standard M1 path). We cannot subclass an *existing instance*, but we don't need to — our `PlaqueLocalSqlMinMaxAggregateFunction` constructor takes the same parameters as `SqlMinMaxAggregateFunction`. The factory captures those parameters at serialization time by also carrying the `IScalarEvaluatorFactory[]` args, `isMin`, `SourceLocation`, and `IAType aggFieldType`. The `inner` factory is not invoked at runtime; it is used only as a carrier for these closed-over values.

In practice, the simplest path: the wrapping factory carries all the constructor args explicitly (mirror what `LocalSqlMaxAggregateDescriptor.createAggregateEvaluatorFactory` does at lines 45–55, substituting the returned type):

```java
public class PlaqueLocalAggregateEvaluatorFactory implements IAggregateEvaluatorFactory {
    private static final long serialVersionUID = 1L;

    private final IScalarEvaluatorFactory[] args;
    private final boolean isMin;
    private final SourceLocation sourceLoc;
    private final IAType aggFieldType;
    private final String handle;
    private final boolean isMax;

    public PlaqueLocalAggregateEvaluatorFactory(IScalarEvaluatorFactory[] args, boolean isMin,
            SourceLocation sourceLoc, IAType aggFieldType, String handle, boolean isMax) {
        this.args = args;
        this.isMin = isMin;
        this.sourceLoc = sourceLoc;
        this.aggFieldType = aggFieldType;
        this.handle = handle;
        this.isMax = isMax;
    }

    @Override
    public IAggregateEvaluator createAggregateEvaluator(IEvaluatorContext ctx) throws HyracksDataException {
        FilterState state = FilterStateRegistry.getOrCreate(ctx.getTaskContext(), handle, isMax);
        return new PlaqueLocalSqlMinMaxAggregateFunction(
                args, ctx, isMin, sourceLoc, aggFieldType, state);
    }
}
```

This requires `PlaqueAggregatePOperator` (§7) to extract the constructor args from the aggregate expression at plan time, rather than delegating to `expressionRuntimeProvider.createAggregateFunctionFactory`. The extraction mirrors the existing descriptor path:

#### Revised `PlaqueAggregatePOperator.contributeRuntimeOperator` (final version)

```java
    @Override
    public void contributeRuntimeOperator(IHyracksJobBuilder builder, JobGenContext context,
            ILogicalOperator op, IOperatorSchema opSchema, IOperatorSchema[] inputSchemas,
            IOperatorSchema outerPlanSchema) throws AlgebricksException {
        AggregateOperator aggOp = (AggregateOperator) op;
        List<Mutable<ILogicalExpression>> expressions = aggOp.getExpressions();
        IAggregateEvaluatorFactory[] aggFactories = new IAggregateEvaluatorFactory[expressions.size()];
        IExpressionRuntimeProvider exprProvider = context.getExpressionRuntimeProvider();

        for (int i = 0; i < aggFactories.length; i++) {
            AggregateFunctionCallExpression aggFun =
                    (AggregateFunctionCallExpression) expressions.get(i).getValue();
            FunctionIdentifier fid = aggFun.getFunctionIdentifier();
            boolean isMin = fid.equals(BuiltinFunctions.LOCAL_SQL_MIN);

            // Compile the scalar argument (same as the standard path does internally).
            IScalarEvaluatorFactory[] scalarArgs = new IScalarEvaluatorFactory[aggFun.getArguments().size()];
            for (int j = 0; j < scalarArgs.length; j++) {
                scalarArgs[j] = exprProvider.createEvaluatorFactory(
                        aggFun.getArguments().get(j).getValue(),
                        context.getTypeEnvironment(op.getInputs().get(0).getValue()),
                        inputSchemas, context);
            }

            // Resolve aggFieldType (same as AbstractMinMaxAggregateDescriptor.setImmutableStates).
            IAType aggFieldType = (IAType) context.getTypeEnvironment(op.getInputs().get(0).getValue())
                    .getType(aggFun.getArguments().get(0).getValue());

            aggFactories[i] = new PlaqueLocalAggregateEvaluatorFactory(
                    scalarArgs, isMin, aggFun.getSourceLocation(), aggFieldType, handle, isMax);
        }

        AggregateRuntimeFactory runtime = new AggregateRuntimeFactory(aggFactories);
        runtime.setSourceLocation(aggOp.getSourceLocation());
        RecordDescriptor recDesc = JobGenHelper.mkRecordDescriptor(
                context.getTypeEnvironment(op), opSchema, context);
        builder.contributeMicroOperator(aggOp, runtime, recDesc);
        ILogicalOperator src = aggOp.getInputs().get(0).getValue();
        builder.contributeGraphEdge(src, 0, aggOp, 0);
    }
```

The `aggFieldType` resolution via `context.getTypeEnvironment().getType()` matches how the existing descriptor path resolves it — see `ExpressionTypeComputer` and `AbstractMinMaxAggregateDescriptor.setImmutableStates` which receives the type from `StaticTypeCastUtil`. If the exact resolution path differs at implementation time, use the same approach that `LocalSqlMaxAggregateDescriptor` uses to set `aggFieldType` in its descriptor chain.

**No `AbstractMinMaxAggregateDescriptor` change needed.** The earlier version of this document proposed adding a `createPlaqueLocalAggregateEvaluatorFactory` helper on the descriptor. That is unnecessary — the `PlaqueLocalAggregateEvaluatorFactory` (this section) carries all the needed parameters directly and constructs the wrapper evaluator without touching the descriptor class.

### 9. `PlaqueRewriteRule` — pre-assign both POperators, share one handle
**Path:** `asterixdb/asterix-algebra/src/main/java/org/apache/asterix/optimizer/rules/PlaqueRewriteRule.java`

**Changes vs. M1:**
- Generate a plan-unique `handle` (e.g., `"plaque-" + System.identityHashCode(aggOp) + "-" + context.newVar().getId()`).
- Pre-assign `PlaqueFilterPOperator(filteredVar, isMax, handle)` on the inserted `SelectOperator`.

## Startup / shutdown lifecycle of FilterState

State objects are held in the task's `IOperatorEnvironment`, which is per-task and owned by the task's lifecycle. When the task ends, its environment is released. No explicit cleanup is required in M1; the FilterState becomes unreachable with the task context.

If a future milestone outlives a single task (cross-task reuse), the registry helper can be repointed at `IJobletEventListenerFactory` or a keyed NC-level map; the filter / aggregate code in this milestone does not change.


## Correctness argument

Unchanged from M1, with one refinement:

1. **The true max still always reaches the aggregate.** The wrapper aggregate receives every tuple that the filter passes. Since `passes(v)` is `v >= threshold` (MAX) and the threshold reflects only values that *actually flowed through the aggregate*, the threshold is bounded above by the running max. Any strictly larger value passes; equal values pass; strictly smaller values drop. All dropped values are < some already-processed value, so they cannot be the maximum.

2. **No update/read race.** Within a partition, `nextFrame` runs single-threaded. For each tuple the sequence is `filter.passes(v)` → (if pass) `aggregate.step(v)` → (if strengthening) `filterState.update(v)`. There is no window where `passes()` observes a stale write: a write in tuple `i` happens-before the `passes()` read in tuple `i+1` on the same thread.

3. **Read-before-write ordering on the first tuple.** The first tuple arrives *after* `open()` has cascaded through both operators. At this point `filterState.initialized = false`, so `passes()` returns `true` unconditionally. The aggregate then processes the tuple and the hook sets `initialized = true`. From tuple 2 onward, the steady-state invariant in (1) holds.

4. **Each partition is independent.** Each task partition has its own task context, hence its own FilterState. M1 has no cross-partition propagation.

5. **NULL/MISSING handling unchanged.** Filter passes them through without consulting `filterState`. Aggregate's `step()` routes them via `processNull` (before any compare), so `onMinMaxChanged` is not called for NULL/MISSING.
